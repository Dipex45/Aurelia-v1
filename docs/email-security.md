# Aurelia Ops: Enterprise Email Authentication and Analytics Protocol

To maximize delivery inbox placement ratios, avoid spam folder classification, and conform strictly with current GMail/Yahoo sender policies, Aurelia Ops implements SPF, DKIM, DMARC domain validation and handles real-time webhooks for delivery, bounces, complaints, and unsubscribed events.

---

## 1. Domain Authentication Specifications (SPF, DKIM, DMARC)

All transactional and notification mail systems must originate from authenticated domains. The specifications for our DNS configurations are detailed below:

### 1.1 SPF (Sender Policy Framework)
Prevents spoofing by defining exactly which hosts/IPs are permitted to deliver email on behalf of your domain name.
- **DNS Record Type**: `TXT`
- **Host**: `@` (or subdomain like `mail.aureliaops.com`)
- **Required Value**: `v=spf1 include:amazonses.com include:mailgun.org include:sendgrid.net include:sp.resend.com ~all`
- *Instruction*: Replace specific `include:` strings with your active email endpoint partner (e.g. Resend / AWS SES / Mailgun). The terminal switch `~all` establishes a soft-fail scenario, allowing testing verification logs prior to transition to strict `-all` enforcement.

### 1.2 DKIM (DomainKeys Identified Mail)
Provides cryptographic verification of the email source and body state integrity.
- **DNS Record Type**: `CNAME` (or `TXT` for custom selective keys)
- **Hosts**: 
  - `resend1._domainkey`
  - `resend2._domainkey`
- **Values**: Point to keys generated by your mail platform provider.
- *Instruction*: These tokens authenticate that emails signed by private keys matches public credentials embedded on corporate DNS servers.

### 1.3 DMARC (Domain-based Message Authentication, Reporting, and Conformance)
Empowers the corporate domain owner to define how receivers should handle messages if they fail SPF or DKIM checks.
- **DNS Record Type**: `TXT`
- **Host**: `_dmarc` (or `_dmarc.aureliaops.com`)
- **Required Production Value**: `v=DMARC1; p=reject; pct=100; rua=mailto:dmarc-reports@aureliaops.com; ruf=mailto:security-forensics@aureliaops.com; fo=1`
- **Parameters**:
  - `p=reject`: Instructs recipient servers to immediately decline/block and drop messages that violate authenticity checks.
  - `pct=100`: The policy applies to 100% of outbound items.
  - `rua`: Aggregate report destination to track volume patterns.
  - `ruf`: Real-time forensic diagnostic endpoint.

## 2. Real-Time Security Ingestion: Email Analytics Webhook Web-Controller

To track deliverability status, process bounce complaints, and ensure zero-spam compliance across critical workspace operations, the enterprise API supports Resend/SES webhook callback ingestion.

### Webhook Event Processing Engine:
Create or mount the following route in `routes.ts` or as part of the system modules:

```ts
// src/server/routes/emailWebhooks.ts
import { Router, Request, Response } from "express";
import crypto from "crypto";

const router = Router();
const WEBHOOK_SIGNING_SECRET = process.env.EMAIL_WEBHOOK_SECRET;

/**
 * POST /api/webhooks/email-analytics
 * Processes incoming webhooks for bounces, spam reports, clicks, and deliveries.
 */
router.post("/api/webhooks/email-analytics", async (req: Request, res: Response) => {
  const signature = req.headers["x-webhook-signature"] as string;

  // 1. Authenticate hook parameters to prevent spam injection
  if (WEBHOOK_SIGNING_SECRET && signature) {
    const computed = crypto
      .createHmac("sha256", WEBHOOK_SIGNING_SECRET)
      .update(JSON.stringify(req.body))
      .digest("hex");
    
    if (signature !== computed) {
      return res.status(403).json({ error: "Invalid webhook credentials signature." });
    }
  }

  const { type, data } = req.body; // standard Resend or SES schema payloads

  console.log(`[Email-Analytics] Webhook received type: [${type}] for recipient: ${data?.email}`);

  try {
    switch (type) {
      case "email.bounced":
        // 1. Log critical hard-bounce to permanent bounce-blacklist DB
        await recordHardBounce(data.email, data.bounce_type, data.diagnostic_code);
        // 2. Alert operations if recipient was assigned critical operator notifications
        await handleSystemOperatorNotificationSuspension(data.email);
        break;

      case "email.complained":
        // Mark user choice as dynamic opt-out to satisfy absolute zero-spam requirements
        await registerSpamComplaint(data.email, data.complaint_type);
        break;

      case "email.delivered":
        // Update notification trace ledger to cleared stats
        await updateDeliverySuccessState(data.email_id, data.delivered_at);
        break;

      case "email.unsubscribed":
        // Dynamic Unsubscribe list enforcement
        await enforceOptOutUnsubscribe(data.email, data.workspace_id);
        break;

      default:
        console.log(`[Email-Analytics] Unhandled hook classifier: ${type}`);
    }

    res.status(200).json({ status: "acknowledged" });
  } catch (err: any) {
    console.error("[Email-Analytics] Action processing exception:", err.message);
    res.status(500).json({ error: "Processing failed internally." });
  }
});

async function recordHardBounce(email: string, reason: string, code: string) {
  console.warn(`[Deliverability Threat] Recipient address hard-bounced permanently. Email: ${email}, Reason: ${reason}, Code: ${code}`);
}

async function registerSpamComplaint(email: string, feedback: string) {
  console.error(`[Deliverability Threat] Spam complaint registered by operator: ${email}, Feedback class: ${feedback}`);
}

async function updateDeliverySuccessState(emailId: string, timestamp: string) {
  console.log(`[Deliverability Verification] Successful delivery logged for thread tracker: ${emailId} at ${timestamp}`);
}

async function enforceOptOutUnsubscribe(email: string, workspaceId?: string) {
  console.log(`[Compliance Directive] Enforcing immediate unsubscribe opt-out for recipient: ${email} in scope workspace: ${workspaceId || 'GLOBAL'}`);
}

export { router as emailWebhooksRouter };
```

## 3. Unsubscribe Handling & Opt-Out Strategy

- **Header Insertion**: Every outgoing promotional or general message includes standard unsubscribe indicators in RFC-certified template margins:
  - `List-Unsubscribe: <https://aureliaops.com/unsubscribe?email=operator@email.com>`
  - `List-Unsubscribe-Post: List-Unsubscribe=One-Click`
- **Verification Engine**: Database layouts track the unsubscribe flag directly under the respective user model or operational boundary (e.g., `user_unsubscribed: boolean`). Real-time delivery triggers evaluate boolean state triggers and block processing before any third-party API execution.
